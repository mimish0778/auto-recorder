# 10s Take Recorder（研究用）

ブラウザだけで動く、カウントダウン付きの10秒動画収録ツールです。全被験者を**同じフレーミング・同じ尺・同じフレーム数**で収録することを目的にしています。`index.html` 単体で完結しており（外部ライブラリへの依存なし）、ローカルで開くほか、GitHub Pages などに置いて URL から利用できます。

## 特徴

- 1テイク＝**10秒（30fps × 300フレーム）**を目標に収録（実フレーム数は数フレーム前後することがあります。「実フレーム数のばらつき」を参照）
- 出力は常に **540×960ピクセル（縦長 9:16）固定**
- **音声は一切収録しません**（研究仕様。マイクにもアクセスしません）
- 顔の大きさ・位置を被験者間で揃えるための**顔ガイド枠**を常時表示
- 保存されるのは**動画ファイルのみ**（付随データファイルは出力しません）

## 動作環境

- `getUserMedia` と `MediaRecorder` に対応したモダンブラウザ（Chrome / Edge / Safari など）
- **カメラのアクセス許可が必要**（マイクは使用しません）
- **PC（デスクトップ版ブラウザ）での使用を強く推奨します。** スマートフォンでの収録は仕様どおりの出力が得られないことが確認されています（下記「収録端末について」を参照）
- 収録中は画面が消灯しないよう自動でスクリーンロックを抑止します（対応ブラウザのみ）

### カメラが動作する条件

ブラウザはカメラへのアクセスを **HTTPS または localhost でのみ** 許可します。

- 公開URL（GitHub Pages など、HTTPS）から開けば問題なく動作します
- ローカルの `index.html` をダブルクリックして開いた場合（`file://`）は、**ブラウザによってはカメラが起動しません**。その場合は公開URLから開くか、ローカルサーバ（例：`python -m http.server`）経由で `http://localhost:8000` として開いてください

### 収録端末について

**研究データの収録には PC を使用してください。**

PC（Chrome 系デスクトップ版）では、フレーム完全一致モードが動作し、仕様どおりの出力が安定して得られることを実測で確認しています。

| 項目 | PC（実測） | スマートフォン（実測） |
|---|---|---|
| 解像度 | 540×960（仕様どおり） | 360×640（仕様と異なる） |
| 実フレーム数 | 298〜301 | 233（大幅に不足＝実質23fps台） |
| 尺 | 10.00秒前後 | 9.97秒 |

スマートフォンでは、フレーム完全一致モードが利用できず時間ベースモードにフォールバックするうえ、端末の処理能力やブラウザの再エンコードの影響でフレームが大量に欠落します。解像度も仕様と一致しません。

**PCとスマートフォンで収録したデータは、解像度もフレームレートも異なるため同一データセットとして混在させないでください。** 収録環境は1つに固定し、カメラ・照明・被験者との距離も含めて全テイクで統一してください。

### 収録データの取り扱い

- 収録した動画は**どこにもアップロードされません**。処理はすべてブラウザ内で完結し、動画は端末のダウンロードフォルダに保存されます
- **被験者の動画を公開リポジトリにコミットしないでください。** 収録データはリポジトリ外で管理してください

## 使い方（1テイクの流れ）

1. **Position** ボタンで `pos0`〜`pos4` を選ぶ（ファイル名に使うラベル）
2. **Start #** に保存するファイル番号を入力する（例：`4` → `pos2_004.mp4`）
3. **START** を押す
4. 画面中央に **3・2・1** のカウントダウンが表示される
5. カウントダウン終了と同時に **10秒間の録画** が自動的に始まる
6. 10秒経過すると **自動的に停止・保存** され、待機状態に戻る

### テイク番号について

**番号は自動では増えません**（意図的な仕様です）。

- 同じ番号のまま何度でも撮り直せます
- 位置だけを変えるなら番号は据え置きでOK（例：`pos0_001` の次に Position を `pos1` にして `pos1_001`）
- 別番号にしたいときは **Start # を手動で書き換えて** からもう一度STARTを押す

**撮り直しても前のファイルは上書きされません。** 同名のファイルが既にある場合、ブラウザが `pos2_001 (1).mp4` のように別名で保存します。同じ番号で複数回撮った場合は、**どれを採用するかを決めて不要なファイルを削除**してください（解析時の取り違え防止）。

同一セッション内ですでに保存した番号を再び使うと、ログに重複警告（`DUPLICATE name`）が出ます。

## STOPボタンについて

STOPは「中断・キャンセル」専用です。

- カウントダウン中に押す → 録画は始まらず、キャンセルされる
- 録画中（10秒経過前）に押す → **そのテイクは破棄され、保存されない**
- **10秒を満了したテイクだけが保存されます**

## 収録が自動で破棄される条件

次の場合、そのテイクは保存されません（ログに `✖ Discarded` と表示）。

- 10秒（300フレーム）に到達する前に停止した
- 録画中にアプリ／タブがバックグラウンドに切り替わった（タイミングが壊れるため無効化）

## 保存後の自動検証

満了したテイクは保存されますが、同時に品質チェックが行われ、結果がログに出ます。

- `✔ Saved ...` … 尺・フレーム間隔ともに正常
- `⚠ Saved ... FLAGGED: ...` … 保存はされたが要注意。主な理由は、実尺が10秒から±0.3秒を超える／フレーム間隔の乱れ／アップスケール／時間ベース収録／番号重複

**FLAGGED付きでも動画自体は保存されます。** 研究データとして使う前にログを確認してください。

## 保存されるファイル

- ファイル名：`{position}_{番号3桁}.拡張子`（例：`pos2_004.mp4`）
- 拡張子：ブラウザが対応するコーデックにより `mp4` または `webm`
- 解像度：**540×960（縦長 9:16）固定**。カメラの実解像度に関わらず、常にこのピクセルサイズで保存
- 音声：**なし**（音声トラックを含みません）
- 保存先：ブラウザの標準ダウンロードフォルダ（このツール自体はフォルダ分けを行いません）

## フレーム精度と収録モード

- 対応ブラウザでは **フレーム完全一致モード** で動作し、30fps × 10秒＝300フレームを1枚ずつ制御して収録します
- ブラウザがこの方式に非対応の場合は **時間ベースモード** に自動でフォールバックし、黄色い警告バッジが出ます。この場合、実フレーム数は300から前後することがあります
- **【重要】** 収録側の要求フレーム数は「エンコード後の実フレーム数」を保証しません。研究データとして厳密に扱う場合は、保存後に `ffprobe -count_frames` で実フレーム数を必ず確認してください

### 実フレーム数のばらつき（既知の挙動）

フレーム完全一致モードで動作していても、**エンコード後の実フレーム数は300ちょうどにならないことがあります。** 実測では 298〜301 程度のばらつきが確認されています（尺も 9.95〜10.01秒程度で対応して変動）。

これは不具合ではなく、ブラウザの `requestFrame()` が「呼び出し1回につき必ず1フレーム出力する」ことを保証しないために生じる仕様上の挙動です。端末の負荷やエンコード状況により、フレームが落ちたり余分に出力されたりします。アプリ側では制御できません。

**解析時の対応（重要）**

- **「先頭300フレームを使う」という前処理は使えません**（298フレームのファイルでは成立しないため）
- 全テイクを揃えるには、**等間隔にNフレーム抽出**する（例：どのファイルからも等間隔に290フレーム）か、**時間で正規化**してください
- 10秒に対する±数フレームは約0.7%・数十ミリ秒の差であり、咀嚼のような連続運動の解析では通常許容範囲です
- 極端に外れたテイク（例：290未満／310超）のみ、除外または撮り直しを検討してください


## 顔ガイドについて

- 画面中央に破線の楕円ガイドが常時表示されます。被験者の顔の大きさ・位置を揃えるための目安です
- **ガイドは表示専用で、録画データには一切写り込みません**（映像とは別レイヤーで描画）

## プレビューについて

- プレビューは、実際に保存される範囲と同じ **縦長 9:16** で表示されます（見えている範囲＝保存される範囲）。カメラ映像は、横幅を**中央基準**でトリミングして 540×960 の枠に収めます（縦は上端基準。カメラがこの枠より縦長の場合のみ下側を調整）
- 前面カメラ使用時、プレビューは見やすさのため左右反転（ミラー）表示されますが、これは表示上だけの処理です。**保存される動画は常にカメラが捉えた実際の向き（ミラーなし）で記録されます**

## 画面の見方

| 表示 | 意味 |
|---|---|
| 上部中央「FRONT / BACK camera」 | 現在使用中のカメラの種別 |
| 右上のカメラアイコン | 前面／背面カメラの切り替えボタン |
| 黄色バッジ「Source resolution below target」 | カメラの実解像度が540×960に届かず、映像を引き伸ばして保存している状態 |
| 黄色バッジ「Frame-lock unsupported — TIME-BASED」 | フレーム完全一致に非対応。フレーム数が変動しうる |
| 赤い「Recording」＋タイマー | 録画中であることと進捗（完全一致モードは `123/300`、時間ベースは `00:07` 表示） |
| 下部のログ | 現在の状態（準備完了・録画中・保存・破棄・警告など）を文字で表示 |

## ロック仕様

録画中・カウントダウン中は、誤操作でテイクが台無しになるのを防ぐため、以下がロックされます。

- Position（撮影区間ラベル）の変更
- Start #（番号）の変更
- 前面／背面カメラの切り替え

STOPを押すか、10秒経過して自動停止すると、ロックは解除されます。

## トラブルシューティング

| 症状 | 対処 |
|---|---|
| 黄色バッジ（below target）が出る | カメラの実解像度が540×960未満のため引き伸ばして保存中。録画自体は問題なく行える |
| 黄色バッジ（TIME-BASED）が出る | フレーム完全一致に非対応。フレーム数が大きく変動するため、**研究データの収録には使わないでください**。PC（Chrome 系デスクトップ版）で実行する |
| カメラ切替ボタンが反応しない | 録画中・カウントダウン中は切替不可（仕様どおり）。STOPを押してから切り替える |
| Position / Start # が変更できない | 録画中・カウントダウン中はロックされる仕様。STOPを押すと解除される |
| カメラの映像が出ない／エラーが出る | ブラウザのカメラ許可設定を確認する。画面下部のログにエラーメッセージが表示される |

## 研究運用上の注意

- 解像度・フレーミング（540×960）を変更すると、顔の写り方（顔占有率）の基準も変わります。**データ収集を始める前に設定を固定**し、途中で変更しないでください（旧設定と混在させると一貫性が崩れます）
- 録画は**ミラーなし**で保存されます。前面カメラでは、被験者の解剖学的な右はフレーム上では**左側**に写ります。左右ラベルの定義（被験者側か／フレーム側か）を統一し、機械学習で使う場合は**水平反転のデータ拡張を無効化**してください（画像を左右反転するとラベルと矛盾します）
- 収集後は各動画を `ffprobe` で「**実フレーム数（300前後）／ 音声トラックなし ／ 540×960**」の3点を確認することを推奨します

### 検証コマンド

サイズ・実フレーム数・尺の確認（`width=540` `height=960` `duration≈10.0` で、`nb_read_frames` が300前後なら正常）：

```
ffprobe -v error -count_frames -select_streams v:0 -show_entries stream=width,height,nb_read_frames -show_entries format=duration -of default=noprint_wrappers=1 pos2_001.mp4
```

音声トラックが無いことの確認（**何も表示されなければ正常**）：

```
ffprobe -v error -select_streams a -show_entries stream=index -of csv=p=0 pos2_001.mp4
```
