# 10s Take Recorder

研究データ収録用の、ブラウザで動く 10 秒動画レコーダーです。3 秒のカウントダウンのあと、カメラ映像を 540x960（縦長 9:16）、30fps、10 秒、音声なしの動画として保存します。

すべての被験者を同じフレーミング・同じ尺・同じフレーム数で撮ることを目的にしています。`index.html` 1 ファイルで完結しており、外部ライブラリには依存しません。

**公開ページ:** https://mimish0778.github.io/auto-recorder/

## 特徴

- 1 テイク 10 秒（30fps x 300 フレーム）を自動で収録・停止・保存
- 出力解像度は 540x960 に固定（カメラの解像度に関係なく同じサイズで保存）
- 音声は収録しない（マイクへのアクセス自体を要求しない）
- 顔の大きさと位置を揃えるための楕円ガイドを表示（録画には写り込まない）
- 保存後に尺とフレーム間隔を自動で検証し、問題があれば画面のログに警告を表示
- 途中で止めたテイクや、録画中にタブが裏に回ったテイクは自動で破棄
- 録画中は画面の消灯を抑止（Screen Wake Lock API に対応したブラウザのみ）
- 動画はブラウザ内で処理され、どこにもアップロードされない

## 動作環境

- `getUserMedia` と `MediaRecorder` に対応したブラウザ
- カメラのアクセス許可
- 安全なコンテキスト（HTTPS または `localhost`）。ブラウザはこれ以外の場所からのカメラ利用を制限します

研究データの収録には PC のデスクトップ版ブラウザを使ってください。理由は「[収録端末による違い](#収録端末による違い)」を参照してください。

## 起動方法

### 公開ページから使う

https://mimish0778.github.io/auto-recorder/ を開き、カメラの使用を許可します。

### ローカルで使う

```bash
git clone https://github.com/mimish0778/auto-recorder.git
cd auto-recorder
python3 -m http.server 8000
```

ブラウザで http://localhost:8000/ を開きます。`index.html` をダブルクリックして `file://` で開くと、ブラウザによってはカメラが起動しません。

## 使い方

1. **Position** で `pos0` から `pos4` のいずれかを選びます（初期値は `pos2`）。ファイル名の先頭に使われるラベルです。
2. **Start #** に保存するファイルの番号を入力します（1 以上の整数。例: `4` なら `pos2_004.mp4`）。
3. **START** を押します。
4. 画面中央に 3、2、1 とカウントダウンが表示され、終わると同時に録画が始まります。
5. 10 秒たつと自動で停止し、動画がダウンロードされて待機状態に戻ります。

右上のボタンで前面カメラと背面カメラを切り替えられます。プレビュー映像をタップすると、下部の操作パネルの半透明表示を切り替えられます。

### テイク番号

番号は自動では増えません。同じ番号のまま何度でも撮り直せます。別の番号にするときは、Start # を書き換えてから START を押してください。

同じ名前のファイルがすでにダウンロードフォルダにある場合、ブラウザが `pos2_001 (1).mp4` のように別名で保存するため、前のファイルは上書きされません。撮り直したときは、どのファイルを採用するか決めて不要なものを削除してください。ページを開いてから同じファイル名で 2 回以上保存すると、ログに `DUPLICATE name` の警告が出ます。

### STOP ボタン

STOP は収録の中止専用です。録画中に押すと、そのテイクは保存されずに破棄されます。保存されるのは 10 秒を満了したテイクだけです。

### 操作のロック

カウントダウン中と録画中は、Position、Start #、カメラの切り替えを変更できません。録画が終わるか STOP を押すと解除されます。

## 保存されるファイル

| 項目 | 内容 |
|---|---|
| ファイル名 | `{Position}_{番号3桁}.{拡張子}`（例: `pos2_004.mp4`） |
| 形式 | ブラウザが対応していれば MP4（H.264）、なければ WebM（VP9 またはブラウザ既定） |
| 解像度 | 540x960 |
| フレームレート / 尺 | 30fps / 10 秒（300 フレーム） |
| ビットレート | 8 Mbps を指定 |
| 音声 | なし（音声トラックを含まない） |
| 保存先 | ブラウザの既定のダウンロードフォルダ |

動画ファイル以外（メタデータや JSON など）は出力しません。

## 録画の仕組み

### フレーム完全一致モードと時間ベースモード

ブラウザが `CanvasCaptureMediaStreamTrack.requestFrame()` に対応している場合は **フレーム完全一致モード** で動作します。カメラ映像を canvas に描画し、33.3ms 間隔で 1 フレームずつ録画ストリームへ送り、300 フレームに達したら停止します。録画中のタイマーは `123/300` のようにフレーム数で表示されます。

対応していない場合は **時間ベースモード** に切り替わり、画面に黄色い警告（`Frame-lock unsupported — TIME-BASED`）が表示されます。このモードでは 30fps で canvas をキャプチャし、10 秒経過した時点で停止するため、実フレーム数は 300 から前後します。タイマーは `00:07` のように秒数で表示されます。

### フレーミング

- カメラ映像を 9:16 の枠に合わせて切り抜いてから 540x960 に拡大縮小します。横に長い映像は左右を中央基準で、縦に長い映像は下側を切り落とします（上端基準）。
- プレビューも同じ枠・同じ基準で表示されるため、画面に見えている範囲がそのまま保存されます。
- カメラの解像度が 540x960 に届かない場合は映像を引き伸ばして保存し、黄色い警告（`Source resolution below target — upscaled`）を表示します。
- 前面カメラのプレビューは見やすさのため左右反転して表示しますが、保存される動画は反転しません。

### 自動破棄

次の場合、テイクは保存されず、ログに `✖ Discarded` と理由が表示されます。

- 10 秒（300 フレーム）に達する前に STOP を押した
- 録画中にタブやアプリがバックグラウンドに回った（タイミングが崩れるため）

### 保存後の検証

10 秒を満了したテイクは保存したうえで次の点を確認し、結果をログに表示します。

- 保存した動画の長さが 10 秒 ± 0.3 秒に収まっているか
- 録画中のフレーム間隔が 66.7ms（2 フレーム分）を超えていないか
- 時間ベースモードではないか
- 引き伸ばし（アップスケール）をしていないか
- 同じファイル名で保存済みではないか

すべて問題なければ `✔ Saved pos2_004 — 300f, dur 10.003s.` のように表示されます。いずれかに当てはまると `⚠ Saved pos2_004 but FLAGGED: ...` と理由が表示されます。警告が出た場合も動画は保存されているので、研究データとして使う前にログを確認してください。

## 画面の表示

| 表示 | 意味 |
|---|---|
| 上部中央の `FRONT camera` / `BACK camera` | 使用中のカメラ |
| 右上のボタン | 前面 / 背面カメラの切り替え |
| 赤い `Recording` とタイマー | 録画中であることと進行状況 |
| 黄色の `Source resolution below target — upscaled` | カメラの解像度が足りず、引き伸ばして保存している |
| 黄色の `Frame-lock unsupported — TIME-BASED` | 時間ベースモードで動作している |
| 下部のログ | 準備完了、録画中、保存、破棄、警告などの状態 |

## 研究で使うときの注意

### 収録端末による違い

作者がフレーム完全一致モードで動作する PC（Chrome 系のデスクトップ版ブラウザ）とスマートフォンで収録した実測例です。

| 項目 | PC | スマートフォン |
|---|---|---|
| 解像度 | 540x960 | 360x640 |
| 実フレーム数 | 298〜301 | 233 |
| 尺 | 10.00 秒前後 | 9.97 秒 |

スマートフォンでは解像度が仕様と一致せず、フレームも大きく欠落しました。PC とスマートフォンで収録したデータを同じデータセットに混ぜないでください。カメラ、照明、被験者との距離も含め、収録環境は 1 つに固定してください。

### 実フレーム数のばらつき

フレーム完全一致モードでも、エンコード後のフレーム数がちょうど 300 になるとは限りません。`requestFrame()` は呼び出しごとに必ず 1 フレームが出力されることを保証しないため、上の実測例のように数フレーム前後することがあります。これはアプリ側では制御できません。

- 解析時に「先頭 300 フレームを使う」前処理は使えません。全テイクから等間隔に同じ数のフレームを抽出するか、時間で正規化してください。
- 時間ベースモードで収録したデータは、フレーム数が大きく変動するため研究データには使わないでください。

### 左右の向き

保存される動画は反転していないため、前面カメラでは被験者の右側がフレームの左側に写ります。左右のラベルの定義を統一し、機械学習に使う場合は左右反転のデータ拡張を無効にしてください。

### 設定の固定

出力サイズ（540x960）や切り抜きの基準を変えると、顔の写り方の基準も変わります。データ収集を始める前に設定を決め、途中で変更しないでください。

### データの管理

被験者の動画をリポジトリにコミットしないでください。収録データはリポジトリの外で管理してください。

## 出力の確認

収録した動画は `ffprobe`（[FFmpeg](https://ffmpeg.org/) に同梱）で確認できます。

解像度、実フレーム数、尺の確認（`width=540`、`height=960`、`nb_read_frames` が 300 前後、`duration` が約 10.0 なら正常）:

```bash
ffprobe -v error -count_frames -select_streams v:0 \
  -show_entries stream=width,height,nb_read_frames \
  -show_entries format=duration \
  -of default=noprint_wrappers=1 pos2_001.mp4
```

音声トラックがないことの確認（何も表示されなければ正常）:

```bash
ffprobe -v error -select_streams a -show_entries stream=index -of csv=p=0 pos2_001.mp4
```

## トラブルシューティング

| 症状 | 対処 |
|---|---|
| カメラの映像が出ない | ブラウザのカメラ許可を確認してください。`file://` で開いている場合は、公開ページか `localhost` から開き直してください。エラー内容は下部のログに表示されます。 |
| `upscaled` の警告が出る | カメラの解像度が 540x960 未満です。録画はできますが、映像は引き伸ばされています。 |
| `TIME-BASED` の警告が出る | ブラウザがフレーム完全一致モードに対応していません。PC のデスクトップ版ブラウザで開き直してください。 |
| Position、Start #、カメラ切り替えが操作できない | カウントダウン中と録画中はロックされます。録画の終了を待つか、STOP を押してください。 |

## 既知の問題

- カウントダウン中は画面全体をカウントダウン表示が覆うため、STOP ボタンをクリックやタップで押せません。カウントダウンが終わると録画が始まるので、中止したい場合は録画開始後に STOP を押してテイクを破棄してください。
